# Understand the product request

1. Identify the product outcome and target app without asking technical questions.
2. Record requested, confirmed, excluded, and unresolved behavior. Treat every visible capability absent from requested/confirmed as excluded for this task.
3. Ask only the smallest plain-language question that materially changes behavior. Offer concrete user outcomes, not framework choices.
4. Separate product behavior from required technical completeness such as validation, tests, health, migrations, containers, routes, and backups.
5. Write checkable acceptance examples from the user's perspective.

Complete when every visible behavior has a request or confirmation and the builder can implement without inventing product decisions.
